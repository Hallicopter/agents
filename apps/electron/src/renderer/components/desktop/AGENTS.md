# Embedded Desktop viewer

Shared by Electron and WebUI. Request `desktop:grant` through the existing authenticated workspace RPC/preload API; never expose a server bearer/VNC password, accept arbitrary upstream URLs, or persist grants. The configured WSS URL is server-supplied, path-restricted and credential/query-free. noVNC is bundled/pinned, not fetched from a CDN.

Electron opens Desktop through window-local IPC → `WindowManager.openDesktopWindow`, reusing the trusted workspace/bootstrap preload and auth routing. It is a normal native, movable/resizable/minimizable window, separate from browser/CUA instances. Reopening the same workspace/session focuses its existing viewer. Desktop windows are excluded from saved window state and main-workspace window lookup; close bypasses chat's layered close interception. WebUI opens a same-origin authenticated pop-out. Keep the dev server's exact configured origin (including localhost:5173) unchanged; never invent a renderer URL or pass tokens in query strings.

`DesktopWindow` mounts only the viewer, not AppShell/action-registry global keyboard handlers. Native menu accelerators are bypassed only while the confirmed-control canvas is focused; toolbar focus/native blur restores local shortcuts. noVNC alone handles remote mouse/drag/wheel/keys, with `scaleViewport=true` and `resizeSession=false`.

`viewOnly` is UX only: the gateway independently enforces modes. Default View only preserves legacy `{ready:true}` watch gateways. The simple View only/Control toggle performs an explicit close → fresh `desktop:grant(sessionId, origin, mode)` attempt. Control requires both grant `mode:'control'` and socket `{ready:true,mode:'control',controlExpiresAt}` plus RFB connect; the finite future cutoff must be within five minutes and is displayed as a countdown. Missing/unknown modes or invalid deadlines fail closed. Control remains backend-disabled until independently reviewed/enabled/proven; do not describe the scaffolding as live working control. No clipboard, file transfer, resize protocol, automatic control retry/reconnect, or lease/takeover jargon.

Returning to View only immediately sets `viewOnly=true`, invalidates the previous attempt, closes it and explicitly opens watch. Closing/unmounting/scope change disconnects only this viewer; a new scope always starts watch. Timeouts and disposal must invalidate pending grants/ready/RFB events so stale results cannot reconnect or enable input. Errors must be actionable and sanitized, never raw backend data. Failed Control offers View only/reconnect rather than auto-retrying.

`browser-fixture-client.ts` is only a test bundle entrypoint consumed by the server-side isolated fixture script; it is not imported into the application. Label all fixture artifacts honestly. Production deployment is disabled until explicit entitlement/Origin/upstream configuration is approved; see `docs/desktop-viewer-fork.md`.

Fork branding is cosmetic only: `shared/display-name.ts` provides the Scoville display label, while builder extraMetadata retains the legacy Electron runtime name for identical userData computation. Do not turn a label change into bundle/protocol/config/credential migration or updater changes. The official update feed is unchanged and can overwrite fork changes.
